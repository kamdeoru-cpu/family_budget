# Техническое задание на разработку приложения «Семейный бюджет»

## 1. Общие сведения

- **Наименование:** настольное приложение «Семейный бюджет».
- **Основание:** задание на курсовой проект по дисциплине «Создание программного обеспечения», тема № 42.
- **Исполнитель:** Боровиков Д. В., группа ЭФБО-18-24.

## 2. Назначение

Приложение предназначено для учёта доходов и расходов семьи: ведения журнала денежных
операций, справочников категорий и членов семьи, расчёта баланса и построения отчёта
о распределении денег по категориям за период.

## 3. Требования к функциям

| № | Функция |
|---|---------|
| Ф1 | Добавление, изменение, удаление членов семьи (ФИО, роль) |
| Ф2 | Добавление, изменение, удаление категорий (название, тип «Доход»/«Расход») |
| Ф3 | Добавление, изменение, удаление операций (дата, сумма, категория, член семьи, комментарий) |
| Ф4 | Фильтрация операций по типу и поиск по тексту |
| Ф5 | Показ итогов: сумма доходов, сумма расходов, баланс |
| Ф6 | Отчёт по категориям за период: количество операций и сумма по каждой категории |
| Ф7 | Сохранение отчёта в файл CSV |

## 4. Бизнес-правила

| № | Правило |
|---|---------|
| П1 | Сумма операции — положительное число не более 10 000 000 с точностью до копеек |
| П2 | Дата операции не может быть в будущем и раньше 01.01.2000 |
| П3 | Названия категорий уникальны без учёта регистра |
| П4 | Нельзя удалить категорию или члена семьи, если на них ссылаются операции |
| П5 | Нельзя изменить тип категории, по которой уже есть операции |
| П6 | Если новый расход больше текущего баланса, пользователь должен подтвердить действие |
| П7 | Удаление любой записи и выход из программы требуют подтверждения |

## 5. Требования к интерфейсу

- Оконный интерфейс на русском языке, оформленный по руководству по стилю (`docs/style_guide.md`).
- Отдельное окно для каждой сущности, переход между окнами через главное меню и кнопку «Назад».
- Масштабируемая компоновка с ограничением минимального размера окна.
- Выпадающие списки для выбора значений из справочников.
- Понятные сообщения об ошибках с указанием способа исправления.

## 6. Требования к надёжности

- Проверка всех введённых значений до записи в базу данных.
- Ограничения целостности в самой базе (внешние ключи, `CHECK`, `UNIQUE`).
- Перехват непредвиденных ошибок без аварийного завершения, запись деталей в журнал `data/errors.log`.
- Работа с относительными путями: программа работает после переноса её папки.

## 7. Требования к архитектуре

- Разделение на три слоя: представление (`app/ui`), бизнес-логика (`app/services`),
  доступ к данным (`app/database`).
- Каждая сущность представлена отдельным классом (`app/models`).
- Код оформлен по PEP 8, имена в стиле snake_case (классы — CamelCase).

## 8. Программное и аппаратное обеспечение

- ОС Windows 10/11 (также работает в Linux и macOS при наличии Python с Tkinter).
- Python 3.10 и выше; для .exe-версии Python не требуется.
- Не менее 100 МБ свободного места на диске, разрешение экрана не менее 1024×768.

## 9. Состав документации

- README.md — описание проекта, установка, запуск;
- руководство пользователя (`docs/user_guide.md`);
- руководство по стилю (`docs/style_guide.md`);
- диаграммы (`docs/diagrams`).

## 10. Порядок приёмки

Приложение считается принятым, если все автоматические тесты проходят
(`python -m unittest discover -s tests -t .`) и функции Ф1–Ф7 выполняются
по сценариям руководства пользователя.
